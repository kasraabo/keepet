# پرسشنامه‌ها، پت‌ها، پروفایل متخصصان و تحریریه

## مسیرهای جدید

- `/management/questionnaires`: همه فرم‌ها؛ مشتری، همکاری متخصص، پروفایل پت، سه خدمت، گزارش دامپزشک، نظرسنجی و تیکت. ویرایشگر عنوان، نوع پاسخ، ترتیب، گزینه‌ها، شرط نمایش و اجبار دارد. شناسه سؤال باید یکتا باشد. انواع: متن کوتاه/بلند، انتخاب، رادیو، تأیید، عدد، ایمیل و تاریخ شمسی.
- `/management/support-content`: افزودن، ویرایش و مخفی کردن FAQ.
- `/management/reviews`: تأیید یا مخفی کردن نظر و امتیاز عمومی.
- `/content`: پنل مستقل تحریریه با دسترسی admin و content، بدون داشبورد مالی/عملیات؛ صفحات متنی، پیش‌نویس و بازبینی مقالات، عنوان SEO، توضیح متا، متن سئوی صفحه و نشانی اصلی سایت. حساب آزمایشی تحریریه `09120000007` در دیتابیس تازه ایجاد می‌شود؛ نقش حساب‌های از قبل موجود عوض نمی‌شود. مدیر `09120000005` هم دسترسی دارد.
- `/profile`: مشخصات مشتری؛ حساب تازه پس از OTP این فرم را می‌بیند و سپس به مقصد قبلی، از جمله رزرو نیمه‌تمام، بازمی‌گردد.
- `/provider/profile`: عکس، معرفی، تحصیلات، تخصص و سوابق دامپزشک/گرومر؛ گالری فقط برای گرومر.
- `/specialists/{id}`: صفحه عمومی متخصص فعال و تأییدشده، با نظرهای تأییدشده و میانگین واقعی امتیاز. برای نمونه‌بردار صفحه عمومی نداریم.

## داده و سازگاری

مهاجرت ۷ فقط جداول/ستون‌ها را اضافه می‌کند. سؤال‌ها در business_config و نسخه سؤال همراه پاسخ در form_responses ذخیره می‌شود. پاسخ اولیه رزرو، تعریف سؤال‌ها و مشخصات پت را در answers به صورت snapshot نگه می‌دارد؛ پرسشنامه‌های قدیمی با تغییر عنوان یا حذف سؤال خواندنی می‌مانند. ثبت‌نام متخصص در صف بررسی عملیات می‌ماند و پاسخ‌های اضافی در همان صف قابل مشاهده‌اند.

نام/گونه پت، موضوع اصلی تریاژ، اجزای گزارش پزشکی و امتیازهای اصلی حذف‌پذیر نیستند؛ عنوان و نوع قابل تغییر است، ولی گزینه‌ها باید با شناسه‌های اصلی سازگار بمانند. پذیرش محدودیت تله‌مدیسین و ممنوعیت بیوپسی در منزل مستقل از تنظیم سؤال اجرا می‌شوند. ارزیابی مشتری توسط دامپزشک اختیاری و محرمانه است. سؤال اضافی گزارش را می‌توان «محرمانه» کرد؛ در پرونده صاحب پت نمایش داده نمی‌شود. سایر داده‌های پزشکی در پرونده هر سه طرف قابل مشاهده‌اند و هیچ‌وقت در صفحه عمومی متخصص منتشر نمی‌شوند.

مشتری واردشده بالای مرحله اول پت را انتخاب می‌کند. مشخصات شناخته‌شده دوباره پرسیده نمی‌شوند؛ سؤال‌های جدید پروفایل، اگر پاسخی نداشته باشند، نمایش داده می‌شوند. مالکیت پت از سمت سرور بررسی می‌شود و مقادیر هویتی مخفی قابل جعل نیستند. پت تازه مشتری واردشده همراه ثبت مرحله اول در حسابش ذخیره می‌شود. سال تولد شمسی یا سن تقریبی الزامی است؛ سال تولد معتبر به سن تقریبی تبدیل می‌شود. پت‌های قدیمی بدون هر دو مقدار باید سن را تکمیل کنند.

نظر مشتری فقط پس از تأیید مدیر عمومی می‌شود. تغییر نظر منتشرشده آن را دوباره به وضعیت نیازمند تأیید برمی‌گرداند. تعداد و میانگین فقط از نظرهای واقعی منتشرشده محاسبه می‌شود؛ هیچ امتیاز ساختگی یا یادداشت خصوصی دامپزشک نمایش داده نمی‌شود.

## تقویم، رسانه و سئو

انتخابگرهای تاریخ شمسی‌اند؛ ساعت‌ها به وقت تهران و ذخیره تاریخ در PostgreSQL همچنان استاندارد میلادی است. سرور تاریخ شمسی و ISO را می‌پذیرد؛ تاریخ‌های نامعتبر و روز کبیسه اعتبارسنجی می‌شوند. تقویم محلی و بدون CDN است و بعد از تغییر صفحه با HTMX دوباره فعال می‌شود.

عکس پروفایل و گالری در PostgreSQL جدا از فایل‌های خصوصی چت ذخیره می‌شوند؛ JPEG/PNG/WebP معتبر، تا ۸ MiB و ۲۰ مگاپیکسل، و حداکثر ۲۰ نمونه‌کار. متخصص فقط تصاویر خودش را مدیریت می‌کند. انتشار تصاویر نیازمند اجازه صاحب تصویر است؛ عکس‌ها پس از بارگذاری عمومی‌اند.

متن محتوا escape می‌شود و HTML اجرایی پذیرفته نمی‌شود. مقالات سلامت با همان بازبینی علمی قبلی منتشر می‌شوند. نشانی اصلی برای canonical و `/sitemap.xml` از پنل محتوا تنظیم می‌شود؛ Host درخواست منبع آن نیست. نشانی پیش‌فرض این محیط QA `http://85.198.54.32:8080` است. صفحات خصوصی از ایندکس خارج‌اند. FAQ و تیکت پویا هستند؛ ایمیل تیکت اجباری است، ولی ارسال ایمیل واقعی هنوز متصل نشده است.

## اجرا و بررسی

```bash
cd /root/keepet
git pull --ff-only
COMPOSE_BAKE=false docker compose --progress plain build app
docker compose up -d --no-build
curl --fail http://127.0.0.1:8080/health
```

تنظیم پورت عمومی compose و volumeهای قبلی حفظ می‌شوند. مهاجرت هنگام شروع خودکار است. `down -v` اجرا نکنید. هیچ API پرداخت، OTP یا ارسال ایمیل واقعی به این نسخه اضافه نشده است.

تست Go شامل چهل سال تبدیل رفت‌وبرگشت تقویم، کبیسه، مالکیت پت، اجبار سن، اعتبار پاسخ و نسخه فرم، جدایی نقش تحریریه، FAQ/ایمیل، SEO و حفظ سؤال‌های پاسخ‌داده‌شده است. آزمایش مرورگر در دیتابیس دورریختنی:

```bash
BASE_URL=http://127.0.0.1:8092 PRODUCT_TEST_DATABASE=keepet_product_v2_smoke node scripts/product-browser.cjs
```

این اسکریپت تنظیمات و داده‌های آزمایشی را تغییر می‌دهد؛ فقط روی دیتابیس smoke اجرا شود. فلوهای رزرو، مدیریت و چت نیز اسکریپت‌های مرورگری جدا دارند.
