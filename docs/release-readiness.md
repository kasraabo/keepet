# جمع‌بندی نسخه و بازگشت در آروان

مراحل یک تا دهٔ سند اصلاحات در کد تکمیل شده‌اند. این بسته، بررسی نهایی و ابزار نصب/بازگشت **همان محیط آزمایشی** را اضافه می‌کند. این گزارش به معنی نصب روی `keepet.ir` نیست؛ اجرای این مرحله روی سرور عمومی هنوز انجام نشده است.

## چه چیزی بررسی شده است؟

- مجموعهٔ کامل Go، بررسی هم‌زمانی و `go vet`.
- ارتقای واقعی schema از نسخهٔ ۱۱ به ۲۱ با اطلاعات تاریخی: مشتری، پت، رزرو، تجویز، موجودی نقدی/هدیه/رزروشده، برداشت، شبا، تیکت، مقاله و تنظیمات معرف حفظ می‌شوند. تکرار پایان خدمت یا restart، درآمد تاریخی را دوباره پرداخت نمی‌کند. کلید بازیابی‌شده، اعتبارنامهٔ رمزگذاری‌شدهٔ قبلی را باز می‌کند.
- مسیرهای مرورگری ورود، تأیید درخواست، انتخاب ساعت، حضور، تحویل آزمایش، چت، پیگیری، گوگل با سرویس محلیِ شبیه‌سازی‌شده، محتوا، زیرخدمات و اعلان‌ها. انتخاب دکمه‌های ارسال فرم در تست‌های قدیمی با دکمهٔ تازهٔ کیبورد فارسی سازگار شده است.
- بکاپ و بازیابی PostgreSQL در دیتابیس مستقل؛ تعداد و اثرانگشت ردیف‌های همهٔ جدول‌ها، شامل فایل‌های خصوصی، مقایسه می‌شوند و برنامهٔ بازیابی‌شده راه می‌افتد.
- مسیرهای شکست نصب: شکست بکاپ، قطع فرایند، خطای Compose پس از احتمال شروع مهاجرت و schema ناسالم باوجود پاسخ HTTP. پس از احتمال شروع مهاجرت، نسخهٔ قدیمی روی همان دیتابیس اجرا نمی‌شود.
- تمرین Docker از نسخهٔ قدیمی به جدید و بازگشت به image/دیتابیس/کلید قبلی؛ بکاپ دست‌کاری‌شده پیش از قطع سایت رد می‌شود. داده‌های جدید در دیتابیس اصلی و یک بکاپ دوم باقی می‌مانند. اگر برنامهٔ برگشتی راه نیفتد، فقط همان کانتینر فعلی که پیش‌تر سالم بوده، روی دیتابیس دست‌نخوردهٔ خودش قابل ازسرگیری است.

[خلاصهٔ نتایج ثبت‌شدهٔ این بررسی‌ها](release-validation.json).

بررسی کد و تست‌های محلی، جای آزمون تنظیمات واقعی سرور، پیامک، درگاه یا حساب Google واقعی را نمی‌گیرد.

## پیش از نصب آزمایشی

اسکریپت `scripts/arvan-preflight.sh` فقط وضعیت را می‌خواند: اجرای app/db، حالت توسعه، سلامت داخلی، schema تمیزِ پشتیبانی‌شده، وجود کلید رمزگذاری استاندارد و فضای کافی بکاپ. محتویات اعتبارنامه در خروجی چاپ نمی‌شود. هم‌زمان فقط یک نصب یا بازگشت در همان checkout مجاز است.

از کنسول همان سرور و مسیر `/root/keepet` استفاده شود. نسخهٔ مورد نظر را بعد از دریافت کد به یک commit ثابت تبدیل کنید:

```bash
cd /root/keepet
git fetch origin main
release_commit=$(git rev-parse origin/main)
git show "$release_commit:scripts/arvan-preflight.sh" > /tmp/keepet-preflight.sh
bash /tmp/keepet-preflight.sh /root/keepet
```

پس از بررسی خروجی و انتخاب همان نسخه:

```bash
git show "$release_commit:scripts/update-arvan-trial.sh" > /tmp/keepet-update.sh
bash /tmp/keepet-update.sh /root/keepet "$release_commit"
```

این دستور به‌روزرسانیِ آزمایشی است. `APP_MODE=production` همچنان مسدود است. اسکریپت هیچ DNS، CDN، فایروال، Caddy یا گواهی را تغییر نمی‌دهد و پورت عمومی قبلی را خودسرانه نمی‌بندد. برنامه تا پایان build روشن می‌ماند و برای بکاپ هماهنگ، نوشتنِ آن موقتاً متوقف می‌شود. اگر نویسندهٔ دیگری به دیتابیس متصل است، آن را هم پیش از این کار متوقف کنید.

## چه چیزی برای بازگشت نگهداری می‌شود؟

در پوشهٔ خصوصیِ `/root/keepet-backups/…`:

- dump کامل PostgreSQL و فهرست قابل خواندن آن؛ تعداد و اثرانگشت ردیف‌های تمام جدول‌ها؛ نسخه و وضعیت schema.
- پوشهٔ کلیدهای خصوصیِ برنامه، تنظیمات حل‌شدهٔ Compose و `.env` موجود. این فایل‌ها محرمانه‌اند و نباید در چت، گیت یا مسیر دانلود عمومی قرار بگیرند.
- image قبلی برنامه با برچسب مستقل، شناسهٔ image دیتابیس، commit قبلی و patch تغییرات محلی.
- نسخهٔ مستقل اسکریپت بازگشت، فایل بررسی داده و فهرست SHA256. نشانگر `backup.ready` فقط بعد از تکمیل اجزای لازم نوشته می‌شود.

imageهای برچسب‌خورده و بکاپ‌ها را تا پایان پذیرش نسخه و دورهٔ نگهداری حذف نکنید. برای تحمل خرابی کل ماشین، کپی امنِ خارج از همان سرور از بکاپ و imageها نیز لازم است؛ این ابزار به‌تنهایی بکاپ خارج از سرور نمی‌سازد.

## بازگشت به نسخهٔ قبلی

مسیر **همان بکاپ پیش از نصب موردنظر** را از خروجی نصب انتخاب و در متغیر `backup` قرار دهید. آخرین پوشه را بدون بررسی انتخاب نکنید. ابتدا بررسی بدون تغییر:

```bash
bash "$backup/rollback-arvan-trial.sh" /root/keepet "$backup" --check
```

برای فعال‌کردن بازگشت:

```bash
bash "$backup/rollback-arvan-trial.sh" /root/keepet "$backup" --restore
```

رفتار آن:

۱. کامل‌بودن بکاپ، SHA256 و وجود imageهای قبلی را بررسی می‌کند.
۲. دیتابیس و volume کلید **جداگانه** می‌سازد و بکاپ قدیمی را در آن بازمی‌گرداند. محتوای جدول‌ها با اثرانگشت بکاپ مقایسه می‌شود.
۳. برای لحظهٔ جابه‌جایی، برنامهٔ فعلی را متوقف و از جدیدترین داده‌ها و کلید آن یک بکاپ دیگر تهیه می‌کند. دیتابیس و volume اصلی بازنویسی یا حذف نمی‌شوند.
۴. همان image قبلی را با داده و کلید هم‌زمان آن، روی پورت قبلی اجرا و سلامت، شناسهٔ image و schema را بررسی می‌کند.
۵. مسیر و نام پروژهٔ بازیابی فعال را چاپ و در `/root/keepet/.keepet-recovery` ثبت می‌کند. updater معمولی تا بررسی این وضعیت متوقف می‌شود تا تصادفاً روی پروژهٔ غیرفعال اجرا نشود.

پس از بازگشت، دستورات عملیاتی را با **نام پروژه و فایل Compose چاپ‌شده در خروجی بازگشت** اجرا کنید؛ اجرای سادهٔ `docker compose up` از checkout قبلی، پروژهٔ فعال بازیابی را مدیریت نمی‌کند. پوشهٔ `/root/keepet-recoveries/…` نیز خصوصی است و باید نگهداری شود.

### تکلیف اطلاعات جدید

**سایت برگشتی، اطلاعات زمان بکاپ را نشان می‌دهد.** سفارش‌ها، پیام‌ها یا تراکنش‌هایی که بعد از آن ایجاد شده‌اند در نسخهٔ قدیمی ظاهر نمی‌شوند؛ در دیتابیس اصلی و `before-rollback.dump` حفظ می‌شوند. ادغام خودکار دیتابیس جدید با schema قدیمی انجام نمی‌شود. قبل از ادامهٔ پرداخت، برداشت یا انجام سفارش واقعی، مدیر باید موارد جدید را تطبیق دهد تا پرداخت یا خدمت دوباره انجام نشود. بازگشت خودکار هنگام داشتن پرداخت‌های واقعی جدید مناسب نیست.

اگر بازگشت شکست خورد، برنامهٔ برگشتی متوقف می‌شود. برنامهٔ فعلی فقط در صورتی ازسرگرفته می‌شود که پیش از بازگشت سالم بوده و دیتابیس خودش دست‌نخورده مانده باشد. در صورت schema نیمه‌مهاجرت‌شده، نباید کد قدیمی روی آن اجرا شود؛ خروجی خطا و بکاپ‌ها را نگه دارید و `docker compose down -v` اجرا نکنید.

## پذیرش بعد از نصب یا بازگشت

- سلامت داخلی و HTTPS دامنه، ورود هر نقش و عدم دسترسی نقش نامرتبط.
- یک درخواست آزمایشی در هر خدمت؛ تأیید مستقیم متخصص و حالت کنترل اپراتور؛ پرداخت شبیه‌سازی‌شده و دسترسی صحیح چت.
- ثبت شبا، بررسی مدیریت، برداشت آزمایشی و اعلان‌ها؛ بدون واریز پول واقعی.
- سابقهٔ رزرو/پرونده و فایل‌های خصوصی، محتوا و سئو، ثبت نسخه و انتشار نتیجه فقط توسط نقش مجاز.
- عدم کش عمومیِ حساب، مدیریت، چت و کیف پول در CDN؛ ارتباط CDN تا مبدأ با HTTPS و SNI درست. تنظیم CDN در این مرحله تغییر نمی‌کند.

## وابستگی‌های باقی‌مانده برای استفادهٔ واقعی

| مورد | وضعیت |
|---|---|
| OTP و پیامک یادآوری واقعی | آداپتر ارسال واقعی هنوز متصل نیست؛ کد توسعه نمایش داده می‌شود. |
| پرداخت/بازگشت بانکی واقعی | شبیه‌سازی؛ آداپتر واقعی هنوز پیاده‌سازی و تأیید نشده است. ذخیرهٔ اطلاعات پذیرنده در پنل، اتصال محسوب نمی‌شود. |
| ورود Google واقعی | نیازمند Client ID/Secret و callback ثبت‌شدهٔ HTTPS؛ تست محلی با حساب واقعی Google انجام نشده است. |
| تطبیق نام صاحب شبا | بررسی دستی مدیر؛ سرویس استعلام خودکار وصل نیست. |
| دادهٔ ارائه‌دهندگان، تعرفه‌ها، آزمایشگاه، مناطق و محتوای عمومی | باید در پنل با اطلاعات واقعی تکمیل و تأیید شوند؛ تست‌ها دادهٔ واقعی را جایگزین نمی‌کنند. |
| نصب عمومی | نیازمند اجرای نسخهٔ انتخاب‌شده در کنسول/دسترسی مجاز سرور؛ در این مرحله اجرا نشده است. |

## بازتولید شواهد محلی

```bash
source scripts/env.sh
python3 scripts/release-check.py
python3 scripts/test-deployment.py
python3 scripts/rehearse-arvan-rollback.py
```

ابزار اول فقط دیتابیس‌های تازهٔ محلی با نام `keepet_release_…_test/smoke` می‌سازد و پس از تست حذف می‌کند؛ گزارش و لاگ‌ها در پوشهٔ خصوصی `/tmp/keepet-release-…` می‌مانند. ابزار سوم Docker، image قدیمیِ schema ۱۱، Git object نسخهٔ قبلی و پورت آزاد محلی ۱۸۱۸۰ لازم دارد؛ image قدیمی را می‌توان با `KEEPET_LEGACY_TEST_IMAGE` مشخص کرد. تمرین با origin محلی و volumeهای دورریختنی اجرا می‌شود و هیچ دستوری به آروان یا سایت عمومی نمی‌فرستد.
